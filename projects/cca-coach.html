01 · Architecture

Two halves, one loop.

A Contabo VPS hosts the MCP server behind Caddy TLS termination. Any Claude client — Desktop, claude.ai, Claude Code — connects with a bearer token (or OAuth 2.0 + PKCE for claude.ai). The orchestrator picks the weakest exam domain, dispatches a worker, persists the attempt, updates the score. Same SQLite. Same truth. Every client.

CLIENTS → CADDY → MCP SERVER → PURE-PYTHON CORE → SQLITE · SUB-AGENTS ORCHESTRATED IN-PROCESS
VPS
Contabo · one machine
Caddy terminates TLS at cca.anycalc.in/mcp with auto Let’s Encrypt. uvicorn binds 127.0.0.1:8765; only Caddy can reach it. systemd supervises with Restart=on-failure, NoNewPrivileges, narrow ReadWritePaths. Bearer token in /etc/cca-coach.env chmod 600 — never logged, never in repo.
CORE
Pure Python · thin adapter
cca_coach.core/ is unit-testable without HTTP, without an Anthropic key, without a network. mcp_server.py is a 1-line dispatch into core/ per tool. Replacing SSE with stdio or gRPC doesn’t touch logic. Same hexagonal split banks use to insulate ledger systems from channel changes.
AUTH
Bearer + OAuth 2.0 + PKCE
Bearer for Desktop and Claude Code. Full OAuth 2.0 + PKCE for claude.ai (it requires it). 32 random bytes from secrets.token_urlsafe. Rotation is one line in /etc/cca-coach.env + systemctl restart. Zero downtime; clients reconnect via SSE.
DB
SQLite · shared truth
Single SQLite file with WAL + foreign keys. Five tables: topics, questions, attempts, weak_spots, study_sessions. Same DB across every Claude client — the weak-spot score from a Desktop quiz informs tomorrow’s claude.ai session. Nightly deploy/backup.sh to /var/backups/cca.
02 · The study cycle

Acquire → Consolidate → Reinforce.

A three-phase rhythm. Reading happens outside the tool — primary sources only. Consolidation happens inside the tool through Socratic dialogue. Reinforcement is automatic: tomorrow’s session opens with what was missed yesterday.

Phase 01 · Acquire
Read the source.
Outside the tool. Tier-1 sources only — no second-hand summaries.
  • Anthropic “Building effective agents”
  • modelcontextprotocol.io spec
  • Anthropic Academy CCA path (Skilljar)
Phase 02 · Consolidate
Socratic dialogue.
Inside the tool. The Concept Coach never gives the answer first — it asks me to design before it explains.
  • Quiz attempts logged via MCP
  • Scenario MCQs tagged by domain
  • Code review of my own MCP tools
Phase 03 · Reinforce
Spaced & weighted.
Recency-weighted miss rate per domain drives session selection. Weak spots compound interest until you fix them.
  • Cross-session score persistence
  • Cross-client (Desktop ↔ web)
  • Daily session opens at the weakest

04 · Daily rhythm

45 minutes weekday. 90 minutes weekend.

A study cadence designed to fit between work and life. Source reading happens outside the tool; the Coach handles consolidation and drilling.

  • 15 minSocratic drill via claude.ai connector — Concept Coach asks before it explains
  • 15 minScenario MCQs via QuizGenerator — log_quiz_attempt() on every answer

Weekend session 90 min

05 · Connect from your Claude client

One server, three clients.

The MCP server is reachable from any Claude client. Pattern shown below; the actual bearer token is per-instance and never lives in the public portfolio.

# Claude Desktop — claude_desktop_config.json { "mcpServers": { "cca-coach": { "url": "https://cca.anycalc.in/mcp", "auth": { "type": "bearer", "token": "<your-token>" } } } }
# claude.ai — Settings → Connectors → Add custom connector URL: https://cca.anycalc.in/mcp Auth: OAuth 2.0 + PKCE (handled by the connector) # OAuth callback resolves to the same backing user; one DB across both clients.
This is a personal study tool. The server runs as a single-tenant instance. The bearer token is rotated locally and never appears in this page or any committed file.
